## Issues found

1. **Fresh-skip counter overcounts trailing inputs.** The repeat created exactly 7 submissions and 7 result rows; 43 domains remained fresh. Its materialization reports `fresh_skipped=45`. The page therefore shows 52 processed / 50 selected. In `website_crawl/results.py`, the scan inspects the whole page but advances its cursor only to the last admitted domain. Trailing fresh rows (`almhult.se` and `almi.se`) are counted again. No extra requests were sent for them.
2. **HTML checksum mismatch for academedia.se.** The original saved HTML is 51,094 bytes, with one carriage return, and hashes to `ce5985b464bd679d274134f9d9aa527bb2e17fa00cb7839cb0c1da5dea5c5964`. The JSON archive contains 51,093 bytes after newline normalization and hashes to `bc208a8a732a629a4cc2db05df910af45d576ec0c4f78bd88a1a036173517c26`, but retains the original hash. Verified directly against the crawler server file. Python text-file reading in `captures.py` normalizes the newline while bundling. The description and extracted sections are intact; 42 other successful HTML hashes match.
3. **Failure reporting loses the actual network error.** Browser API catches general Playwright errors as HTTP 409 and the crawler presents them as browser unavailable. Independent checks from the crawler server confirmed DNS/TLS failures in five domains. Six unsuccessful site-info jobs also show operational state `completed` with `crawl_status=needs_review` and an empty top-level error. Their ClickHouse `successful` flag is correctly false, but the attempt list can be misleading and does not offer the failed-job retry controls.

These are validation findings; this test did not patch or redeploy the services.
